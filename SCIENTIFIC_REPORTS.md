# Научные отчёты ALEM WIND

## В интерфейсе

```bash
python -m pip install -r requirements-reports.txt
python serve_preview.py --port 8767
```

Откройте `http://127.0.0.1:8767/preview/#reports`. Выберите источник, дату и горизонт, затем нажмите «Сформировать отчёт». Отчёт всегда охватывает обе турбины; фильтр отдельной турбины на карте к нему не применяется. Смена источника, даты или горизонта убирает старый отчёт из интерфейса.

Обычный `python -m http.server` показывает макет, но не умеет формировать отчёты. `serve_preview.py` — локальный однопользовательский сервер, привязанный к 127.0.0.1; для внешнего развёртывания потребуются аутентификация, очередь задач и ограничения ресурсов.

## Состав отчёта

| Рисунок | Что означает |
| --- | --- |
| Почасовые траектории | Мощность и ветер на общей оси UTC; фактические измерения добавляются только при наличии |
| Рабочие точки P(v) | Связь прогнозной мощности с прогнозным ветром; не паспортная характеристика турбины |
| Обеспеченность мощности | Убывающая последовательность прогнозных значений; доля часов не ниже данного уровня |
| Часовые изменения | Разность соседних мощностей при шаге 1 час, p.u./ч |
| Прогноз против факта | Только совпавшие UTC-часы и турбины; линия 1:1 |
| Ошибки | Временной ряд и гистограмма Pпрогноз − Pфакт; только при наличии наблюдений |

Графики выполнены Matplotlib на белом фоне с основной и дополнительной сеткой, единицами, легендой, номерами и пояснениями. Серии отличаются цветом и формой маркеров или типом линии. PDF и SVG — векторные; PNG имеет разрешение 300 dpi. Оригинальные карты КПД, степени повышения давления и компрессорные характеристики с референса не переносятся на ветроустановку: соответствующих измерений нет. Для определения кривых ветроустановок см. [NREL: Fundamentals of Wind Energy](https://www.nrel.gov/docs/fy23osti/84501.pdf).

## Исходные данные и методика

Для модельного режима сервер читает дневной CSV и соседний JSON-аудит с диска; значения модели из браузерного запроса игнорируются. Проверяются режим, факт обучения, время выпуска, диапазон мощности [0,1], конечность чисел и полные уникальные пары «час—турбина». Запрошенные 24 часа могут быть взяты из полного 48-часового файла после проверки всего источника.

Все отчёты сохраняют UTC. Показатели мощности имеют единицы p.u.; МВт, МВт·ч, номинальная мощность, КПД и доверительные интервалы не выводятся без подтверждённых исходных параметров. Диаграмма P(v) состоит из прогнозных точек. Пороги 3/25 м/с отмечаются только если аудит сообщает их применение. Для текущего модельного ветра на 10 м пороги высоты ступицы не применяются.

Оценка качества использует отдельный файл `outputs/observations.csv` с **почасовой** нормализованной фактической мощностью:

```csv
valid_time,turbine_id,power_normalized
```

Одна строка — один UTC-час и одна турбина (`turbine_1` / `turbine_2`). Время должно содержать `Z` или явное смещение, выравниваться на час; нормировка должна совпадать с прогнозом. Для исходных 10-минутных наблюдений предварительно примените такое же почасовое усреднение, как в пайплайне. Дубликаты и некорректные значения отвергаются. Пропуски не интерполируются; метрики каждой турбины рассчитываются только по совпавшим часам, а n показывает покрытие.

- MAE = mean(abs(prediction − observation)).
- RMSE = sqrt(mean((prediction − observation)²)).
- Bias = mean(prediction − observation); положительное значение означает завышение.

Наблюдения применяются только после формирования прогноза, не поступают в обучение или признаки. Демо нельзя оценивать как модель. При отсутствии совпадений метрики остаются `null`, а соответствующие рисунки отсутствуют. Измерений за февраль в поставленных файлах пока нет. Короткий горизонт не доказывает качество модели за весь месяц.

## CLI и воспроизводимость

```bash
python scientific_report.py --forecast outputs/demo/forecast_20260214T0000Z.csv --horizon 48
# Для реального расчёта с наблюдениями:
python scientific_report.py --forecast outputs/backtest/forecast_20260214T0000Z.csv --observations outputs/observations.csv
```

Отчёты записываются в `outputs/reports/`; UI размещает их дополнительно по источнику. ID включает дату, горизонт и первые 12 символов SHA-256 канонического набора прогнозных значений, аудита и сопоставленных наблюдений. Полный хеш, время создания, методика, статистика и исходный аудит находятся в `metadata.json`. Хеш относится к каноническому содержимому, а не к исходным байтам CSV.

ZIP содержит PDF, автономный HTML со встроенными SVG, отдельные SVG/PNG, выбранный `forecast.csv`, `metadata.json`, при наличии — сопоставленный `observations.csv`, и `SHA256SUMS.txt` с побайтовыми суммами файлов. Генерация не изменяет исходные прогнозы. Материалы создаются локально и не отправляются внешним сервисам.
